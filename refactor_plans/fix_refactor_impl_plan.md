# Refactor Behavior Restoration Plan

## Goal
Restore all user-visible behaviors lost during the coordinator/view refactor, including both spec-defined flows and legacy flows from the pre-refactor UI that still need to exist, using commit `f2788fb` as the behavioral reference baseline.

## Tasks
- [x] Task 1: Reconnect command propagation between views and coordinator in `internal/ui/views/dashboard.go`, `internal/ui/views/card_editor.go`, `internal/ui/views/mcp_form.go`, and `internal/ui/views/ide_config.go` so callbacks that return `tea.Cmd` are always returned to the coordinator instead of being dropped. Verify: `Enter` on a card opens the launcher, `ctrl+e` from skills/personas/MCPs navigates correctly, MCP save returns to the previous screen, and IDE close/save navigation works.
- [x] Task 2: Restore the full dashboard session action semantics from the old app inside `internal/ui/views/dashboard.go` and `internal/ui/callbacks.go`: `Enter` on running session attaches, `Enter` on terminated session relaunches, `s` on terminated session uses switch-agent semantics, delete/remove is limited to terminated sessions with confirmation for tmp sessions, and all failures surface through `messages.ErrorMsg`. Verify: each key produces the same result as pre-refactor and invalid cases show an error instead of silently doing nothing.
- [x] Task 3: Restore the `f2788fb` dashboard preview behavior in `internal/ui/views/dashboard.go`, `internal/ui/components/session_preview.go`, and coordinator/session wiring: keep a stable preview selection when moving between panes, follow the selected session when the sessions pane is focused, recover to another valid session when the previewed one disappears, clear preview when no sessions remain, and load live/current scrollback from the session manager instead of leaving the preview mostly static. Verify: the preview semantics covered by old `app_preview_test.go` work again in the refactored UI.
- [x] Task 4: Restore the `f2788fb` flexible dashboard sizing behavior in `internal/ui/views/dashboard.go` so pane widths are computed like the old `resize()` logic, including preserving a minimum useful cards width by shrinking preview width when necessary instead of using a rigid 25/33/remainder split. Verify: narrow and wide terminal sizes keep cards usable, preview width adapts, and dashboard width allocation matches old behavior closely.
- [x] Task 5: Restore session-launcher behavior in `internal/ui/views/session_launcher.go` and `internal/ui/callbacks.go`: reset launcher state on each open, pass the entered name through launch flow, persist it with `session.SetName`, and preserve the old post-launch behavior of returning to dashboard and attaching when launch succeeds. Verify: launching from a card creates a session with the typed name and immediately opens the attached session flow.
- [x] Task 6: Restore card-editor subflows in `internal/ui/views/card_editor.go`, `internal/ui/views/agentsmd_editor_modal.go`, and coordinator callbacks: workspace picker, puppet selector, agents.md editor/path flow, skill/persona source managers, and MCP form must all round-trip back into the editor with state preserved. Verify: editing any subview returns to the card editor, changes remain in the form, and `Enter` on the card editor saves and returns to dashboard.
- [x] Task 7: Restore registry management side effects in `internal/ui/callbacks.go`, `internal/ui/views/source_manager.go`, and `internal/ui/components/source_list.go`: skill source saves/deletes must call `SyncSkillsFromSources`, persona source saves/deletes must call `SyncPersonasFromSources`, workspace source save/delete must continue to sync discovered workspaces, and workspace manager `r` must trigger discovery refresh. Verify: adding, editing, deleting, and refreshing sources updates the corresponding registries immediately without waiting for a periodic tick.
- [x] Task 8: Restore MCP registry behavior in `internal/ui/views/card_editor.go` and `internal/ui/views/mcp_form.go`: deleting an MCP from the card editor must delete it from the global registry when allowed by repository rules, refresh the MCP list, and keep cursor/selection sane; MCP create/edit must refresh the editor-visible registry immediately. Verify: `Del` on an MCP removes it globally if unused, used MCPs show repository validation errors, and a newly added MCP appears back in the card editor without reopening the app.
- [x] Task 9: Restore IDE integration completeness in `internal/ui/coordinator.go`, `internal/ui/callbacks.go`, `internal/ui/views/ide_config.go`, and `internal/ui/views/ide_launcher.go`: load persisted IDE config via `repo.GetIDEConfig()` when opening the IDE view, handle save errors visibly, and bring back the legacy dashboard action for opening the selected session workspace in the configured IDE. Verify: `i` shows the saved command, editing persists across reopen, and the dashboard IDE-open action launches the configured command against the selected session workspace.
- [x] Task 10: Restore correct navigation context and previous-view handling across coordinator-owned views in `internal/ui/coordinator.go` and `internal/ui/callbacks.go`: source managers and MCP form must return to dashboard or card editor depending on where they were opened from, not always dashboard. Verify: opening MCP form or source managers from dashboard returns to dashboard, while opening them from card editor returns to card editor with form state intact.
- [ ] Task 11: Add behavioral integration coverage in `internal/ui/integration_test.go` plus focused view tests for dashboard, card editor, MCP form, IDE config, source manager, session launcher, and preview/sizing behavior. Verify: tests cover the regressions found here, especially dropped commands, relaunch vs attach logic, preview persistence/recovery/scrollback, flexible pane widths, previous-view restoration, source sync side effects, MCP deletion, IDE persistence/load, and session naming/attach flow.
- [ ] Task 12: Run full verification against the restored flows and compare with the pre-refactor implementation in commit `f2788fb` for any remaining gaps not already covered by the spec. Verify: `go test ./internal/ui/... ./internal/config/... ./internal/session/...` passes, and manual smoke test confirms dashboard/card/session/preview/registry/IDE flows all behave as expected.

## Done When
- [ ] All spec-defined interactions from `kankuro_specs.md` work again in the refactored UI.
- [ ] Legacy behaviors that disappeared during the refactor are restored, including auto-attach after successful launch/relaunch, dashboard IDE-open action, switch-agent semantics, `f2788fb` preview behavior, and `f2788fb` flexible dashboard sizing.
- [ ] No known user action silently fails because a returned command, refresh, or error path is dropped.
- [ ] Regression tests exist for every behavior called out in the restoration report.

## Notes
- Use commit `f2788fb` as the behavioral reference for legacy flows, including preview and dashboard sizing behavior; in conflicts with the spec, keep the spec and port only the supporting legacy logic.
- Prefer restoring behavior by reconnecting coordinator/view message flow, not by reintroducing the old monolithic `App` state machine.
- Treat silent failures as bugs even when the underlying repo mutation succeeds; the restoration target is user-visible behavior, not just persistence.
